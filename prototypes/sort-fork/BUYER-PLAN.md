# BUYER PLAN — securing the >90% commitment (before any build)

*owner: deal-closer · the whole point: get a payer committed FIRST*

## The honest catch in mobile puzzle (stated up front)
Hyper/hybrid-casual publishers usually want to see a **built, CPI-tested prototype before they commit money.** Pay-per-test ($300/test) and burn-rate coverage (Azur, after 2–4 prototypes) kick in *around* building, not strictly before. So a clean "100% paid before we touch code" is harder here than in work-for-hire. There are three ways to stay rule-compliant:

| Route | How it reaches >90% before building | Reality |
|---|---|---|
| **A. Co-dev / work-for-hire brief** | A publisher or larger studio pays us a fee/deposit to build sort-puzzle prototypes to their brief | Cleanest >90%. Requires finding a buyer who contracts prototyping (some do). Pitch on concept + portfolio, no spec build needed. |
| **B. Burn-rate / PPP relationship** | Publisher agrees to cover monthly cost / pay per prototype, then we produce volume | ~90% *once signed*, but they typically want to see we can ship first → entry cost of a sample. |
| **C. Fake-door CPI pre-test** | A no-build creative test (a few ad mockups → measured click/install intent) validates the skin's CPI *before* a game exists | De-risks the concept cheaply; raises confidence, but isn't itself a paying commitment. |

**The catch-22:** if every target requires a built+tested prototype before committing, then under the strict >90% rule we do **not** build a speculative one. We pursue Route A (commit-on-concept) and use Route C to de-risk — and only build when a commitment or a >90%-justifying signal exists. If none materialises, the disciplined answer is **we don't build.** Whether to fund a small, explicitly-budgeted "sales-demo" build as a business-development cost (a narrow, deliberate exception) is a **founder decision — I will not slip one in.**

## Walk-away terms (floors from FINANCE/GATES)
- Per-test/iteration: never build a fork for free beyond an agreed sample; floor build-cost + margin.
- Burn-rate: not below covered monthly cost + 15%.
- Never assign IP before payment; keep non-exclusive where possible (Azur allows it).

## Self-QA (deal-closer)
- *Assumption:* at least one target will engage on a concept/relationship pitch without a finished game. *Confidence:* **~40–55%** to get a conversation; **lower** to get a signed commitment without any sample. Stated honestly, not inflated.
- *What would make this wrong:* all targets gate commitment on a built+CPI-tested prototype (likely for several). Then Route A or "don't build" applies — not a quiet spec build.
- *Pitch integrity check:* this pitch sells a *capability + concept*, with no built artifact dressed up as more than it is. ✅
